# 控件手势矩阵

目的：在改动任何手势前，先看清**现有**行为。之前的教训是——我想把双击改成归位，
却不知道中键已经能归位（`AutomatableModelView.cpp:173`），差点改出功能倒退。

所有结论均来自代码，标注了出处；"实测"列表示已在 Xephyr 里验证过。

---

## 一、三类数值控件

| 控件 | 基类 | 典型位置 | 数值类型 |
| --- | --- | --- | --- |
| 旋钮 Knob | `FloatModelEditorBase` | 乐器窗口、效果器、自动化 | float |
| 推子 Fader | `FloatModelEditorBase` | 混音器通道 | float（内部是振幅） |
| 滑块 AutomatableSlider | `QSlider` + `IntModelView` | 主工具栏 主音量/主音高 | int |

| 手势 | 行为 | 出处 |

| 手势 | 行为 | 出处 |

## 三、由此暴露的不一致

| # | 不一致 | 影响 | 建议 |
| --- | --- | --- | --- |
| 1 | **Ctrl 在拖动上是"链接"，在滚轮上是"细调"** | 用户按 Ctrl 拖动想微调，结果拖出了一个链接 | 不改行为，改文案：tooltip 明确写"Ctrl+拖动=链接" |
| 2 | Shift 在按下时是"复制参数"，在拖动中是"粗调/细调" | 想粗调却开始拖放 | 同上，文案说清 |
| 3 | ~~推子 Alt+滚轮无响应，旋钮是"最细"~~ | 同一手势两种结果 | ✅ 已修：推子 Alt = 0.05 dB（T1-3） |
| 4 | 滑块没有中键归位、没有链接手势、滚轮不吃修饰键 | 同一排控件行为不同 | 至少补中键归位与滚轮修饰键 |
| 5 | 滑块判断 Ctrl 用的是硬编码 `Qt::ControlModifier`，旋钮用 `KBD_COPY_MODIFIER` | macOS 上不一致（⌘ vs Control） | 统一用 `KBD_COPY_MODIFIER` |

## 四、手势文案的呈现方式

最终选择**状态栏悬停提示**（T1-4 已实现），而不是静态 tooltip——后者会把
`FloatModelEditorBase` 的实时数值浮层顶掉。文案按控件族区分，见 `ui-ux-tasks.md` 的 T1-4。

原始的文案草案（供参考）：

按矩阵，文案必须区分"拖动"和"滚轮"，否则会自相矛盾：

```
旋钮：拖动调整 · 滚轮滚动 · Shift+滚轮粗调 · Ctrl+滚轮细调
      中键归位 · 双击输入数值 · 右键更多
推子：拖动调整 · 滚轮 1 dB · Shift 粗调 · Ctrl 细调
      中键归位 · 双击输入数值 · 右键更多
```

不写进 tooltip 的两条（太长且低频）：`Shift+拖动=复制参数`、`Ctrl+拖动=链接`，
它们放在右键菜单里已有入口（"Remove all linked controls" 等），
并在用户文档里说明。

## 六、截图环境说明

本文件里的"实测"都在 Xephyr（裸 X 服务器，无窗口管理器）里完成。该环境下：

- Qt 的 **tooltip、菜单、对话框**都是 32 位 ARGB 顶层窗口，没有合成器就不会被画进根窗口，
  用 `xwd -root` 截出来是**纯黑方块**。这是截图方法的问题，不是 UI 缺陷。
  要看清它们的内容，必须 `xwd -id <窗口 id>` 单独抓（例如值提示窗口抓到的是 `Time: 0ms`）。
- `:focus` 伪状态不会生效（窗口未被激活），所以焦点样式只能在离屏渲染里验证。
- 每次发送按键前重新 `XSetInputFocus` 会让窗口失去激活状态，从而触发就地编辑器的
  "失焦提交"。测试时必须在一次焦点设置后连续发按键。
